# 视觉系统坐标变换原理 (基于项目真实数据)

本文档使用您当前项目中的真实文件和数据（产品 `7777`），来解释系统是如何工作的。

## 1. “标准答案”在哪里？

所有的校准计算都必须基于一个“绝对正确”的标准。在本项目中，这个标准就是您的**配方训练图**。

### 标准模板文件 (The Golden Master)
*   **文件路径**: `h:\CodeForGithub\DIY-Multi-Color-Vision-Guided-Dispensing-Machine\produces\7777\reference.png`
*   **作用**: 这张图片是您当初做“黄金示教”时拍下来的。系统认为这张图里的模具位置是**标准位置 (Angle=0)**。所有的路径都是画在这张图上的。

### 参考原点 (The Anchor Point)
为了计算偏移，系统必须在 `reference.png` 上找一个固定的点作为“0点”（锚点）。
*   **数据来源**: 通常保存在 `config.json` 中，但您的 `produces\7777\config.json` 中记录为 `(0, 0)`。
*   **实际处理**: 当配置为 0 时，系统会自动对 `reference.png` 进行 Halcon 匹配，现场算出一个原点。
*   **真实数值**: 根据您的运行日志，系统算出的**真实原点**是：
    *   **Row (Y)**: `597.57`
    *   **Col (X)**: `1150.59`
    *   这个点就是模具中心的坐标。

### 源路径 (Source Path)
您在编辑器里画的点，都会被保存为相对于图片左上角的坐标。
*   **文件路径**: `h:\CodeForGithub\DIY-Multi-Color-Vision-Guided-Dispensing-Machine\produces\7777\multicolor_path.json`
*   **真实数据举例**: 打开文件可以看到第一个点（Type=dot, Color=0）：
    *   **X**: `1097.38`
    *   **Y**: `490.93`
    *   这个坐标是死死固定在 `reference.png` 上的。

## 2. 实时计算：它是怎么变“活”的？

当您点击【识别模具】时，机器拍摄了一张新照片，发现模具没放正。

### 场景模拟
假设现在的模具（我们称为 **Target**）被识别到了，位置如下（假设值）：
*   **Live Row**: `647.57` (比原点 Y 偏了 +50像素)
*   **Live Col**: `1200.59` (比原点 X 偏了 +50像素)
*   **Angle**: `0` (没旋转)

### 机器的计算逻辑
机器会建立一个方程：
> `Target` = `Source` + `Offset`

代入数据：
*   **X轴偏移**: `1200.59 - 1150.59 = +50`
*   **Y轴偏移**: `647.57 - 597.57 = +50`

### 路径搬运
机器会对您的那个“源路径点” `(1097.38, 490.93)` 执行同样的偏移：
*   **新 X**: `1097.38 + 50 = 1147.38`
*   **新 Y**: `490.93 + 50 = 540.93`

这就是为什么屏幕上的绿线能**精确**压在模具上的原因：它不仅仅是“画”出来的，它是**每一个点都经过了严密的数学搬运**。
